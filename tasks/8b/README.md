# 八下协作白板 · 总规则（契约 v2）

这是**多 AI 协作的唯一联络点**。所有参与方环境互相隔离，彼此不能直接通信，
只能读写本仓库。主流程（调度方）把指令写在这里，其他 AI 读指令、把成果写进指定目录，
主流程再取回结果做校验与后续生产。

> **契约 v2 已生效**：`tasks/8b/数据契约.md` 补齐了子句切分正则、教材原字豁免、
> 长句折行规则，并提供 `自检_课文整理.py` 作为唯一闸门副本。发包前先读 v2 第 4–6 节。

## 目录分工（严格遵守）

| 目录 | 内容 | 谁可写 |
|---|---|---|
| `raw/8b/` | 官方课本 PDF、版本核对说明 | **只读**，任何人不得修改 |
| `pages/8b/` | 按单元导出的正文页纯文本 `.txt` | **只读**，由主流程生成 |
| `tasks/8b/` | 任务卡、任务书、数据契约、自检脚本、音频分包白板 | **只读**，由主流程生成 |
| `results/8b/unitNN/` | 课文整理交回的 3 份 JSON | **只有负责该 unitNN 的 AI 可写** |
| `results/8b/unitNN/audio/` | 语音合成交回的 12 个文件（6× MP3 + 6× timeline） | **只有负责该 unitNN 的 AI 可写** |
| `results/8b/unitNN/video/` | 视频渲染交回的 18 个文件（6 目录 × 视频/音频/封面） | **只有负责该 unitNN 的 AI 可写** |
| `results/8b/status.json` | 调度状态 | **只读**，仅主流程更新 |
| `冀教版/` | 已交付的成品课件（只读，协作阶段一律不碰） | **只读** |

## 铁律

1. 每个 AI **只写自己被指派的 `unitNN/` 目录**（或该目录下的 `audio/`），不得创建、修改、删除其他任何文件。
2. 课文整理只交 3 份 JSON；音频合成只交 12 个文件；视频渲染只交 18 个文件。
   **后两个阶段按契约产出二进制，属允许范围**；除此之外不要提交脚本、日志或临时文件。
3. 不要改 `README.md`、不要改 `tasks/`、不要改 `raw/`、不要改 `pages/`。
   `tasks/` 里的自检脚本**只运行，不修改、不复制进自己的提交**。
4. 一次提交只放自己那单元的文件；文件名必须完全一致，不要加日期、版本号或后缀。
5. 不确定时**宁可留空并写进 `inferred`**，也不要凭记忆补写课本内容。
6. 所有英文必须来自 `pages/8b/` 的正文页文本；中文译文是自译，不是教材原文。
7. **不要自己实现校验逻辑**。闸门只有一份实现，用主流程提供的自检脚本。

## 提交前自检（两个阶段各一份）

| 阶段 | 命令（仓库根目录） |
|---|---|
| ② 课文整理 | `python tasks/8b/自检_课文整理.py unitNN` |
| ④ 语音合成 | `python tasks/8b/audio/自检.py unitNN` |
| ⑥ 视频渲染 | `python tasks/8b/video/自检.py unitNN` |

全绿才提交。两份自检就是主流程闸门的同源副本，判断逐项一致。

## 状态怎么看

`results/8b/status.json` 里每个单元有 `pending / claimed / submitted / accepted / rejected` 五种状态，
另有 `audio` 字段（`ready` 可开工 / `blocked` 待课文修复）。
主流程每轮接手时扫到新提交就跑校验，通过后改成 `accepted`，不通过改成 `rejected` 并把原因写进 `note`。
**其他 AI 不要改这个文件。**

## 需要重试时

主流程会在对应 `unitNN/` 目录放一份 `REJECT.md` 写明哪里不合格、**附完整期望清单**；
负责该单元的 AI 读它、改自己的文件、重新提交即可，不要动别的单元。
