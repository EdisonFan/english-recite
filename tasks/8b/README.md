# 八下协作白板 · 总规则

这是**多 AI 协作的唯一联络点**。所有参与方环境互相隔离，彼此不能直接通信，
只能读写本仓库。主流程（调度方）把指令写在这里，其他 AI 读指令、把成果写进指定目录，
主流程再取回结果做校验与后续生产。

## 目录分工（严格遵守）

| 目录 | 内容 | 谁可写 |
|---|---|---|
| `raw/8b/` | 官方课本 PDF、版本核对说明 | **只读**，任何人不得修改 |
| `pages/8b/` | 按单元导出的正文页纯文本 `.txt` | **只读**，由主流程生成 |
| `tasks/8b/` | 任务卡、任务书、数据契约 | **只读**，由主流程生成 |
| `results/8b/unitNN/` | 各 AI 交回的 3 份 JSON | **只有负责该 unitNN 的 AI 可写** |
| `results/8b/status.json` | 调度状态 | **只读**，仅主流程更新 |
| `冀教版/` | 已交付的 90 课成品 | **只读**，协作阶段一律不碰 |

## 铁律

1. 每个 AI **只写自己被指派的 `unitNN/` 目录**，不得创建、修改、删除其他任何文件。
2. 不要提交二进制文件（PDF、图片、音频、视频），不要提交脚本或临时文件。
3. 不要改 `README.md`、不要改 `tasks/`、不要改 `raw/`、不要改 `pages/`。
4. 一次提交只放自己那 3 个 JSON；文件名必须完全一致，不要加日期、版本号或后缀。
5. 不确定时**宁可留空并写进 `inferred`**，也不要凭记忆补写课本内容。
6. 所有英文必须来自 `pages/8b/` 的正文页文本；中文译文是自译，不是教材原文。

## 状态怎么看

`results/8b/status.json` 里每个单元有 `pending / claimed / submitted / accepted / rejected` 五种状态。
主流程扫到 `submitted` 就跑校验，通过后改成 `accepted`，不通过改成 `rejected` 并把原因写进 `note`。
**其他 AI 不要改这个文件。**

## 需要重试时

主流程会在对应 `unitNN/` 目录放一份 `REJECT.md` 写明哪里不合格；
负责该单元的 AI 读它、改自己的 3 个 JSON、重新提交即可，不要动别的单元。
